📘 MODULE 2 - SOL (SRP + OCP + LSP) FULL PRACTICE NOTES 🚀

=================================================
📌 S - SINGLE RESPONSIBILITY PRINCIPLE (SRP)
=================================================
Definition:
A class should have only ONE reason to change.

---------------------------------
❌ EXAMPLE 1
---------------------------------
class UserService {
    void registerUser() {}
    void sendEmail() {}
}
✅ FIX
class UserService { void registerUser() {} }
class EmailService { void sendEmail() {} }

---------------------------------
❌ EXAMPLE 2
---------------------------------
class Report {
    void generate() {}
    void print() {}
}
✅ FIX
class ReportGenerator {}
class ReportPrinter {}

---------------------------------
❌ EXAMPLE 3
---------------------------------
class Order {
    void calculate() {}
    void saveDB() {}
}
✅ FIX
class Order {}
class OrderRepository {}

---------------------------------
❌ EXAMPLE 4
---------------------------------
class Employee {
    void calculateSalary() {}
    void generatePayslip() {}
}
✅ FIX
class SalaryCalculator {}
class PayslipGenerator {}

---------------------------------
❌ EXAMPLE 5
---------------------------------
class Logger {
    void logToFile() {}
    void logToDB() {}
}
✅ FIX
class FileLogger {}
class DBLogger {}

✅ KEY IDEA: Split by responsibility

📌 O - OPEN CLOSED PRINCIPLE (OCP)
=================================================
Definition:
Open for extension, closed for modification

---------------------------------
❌ EXAMPLE 1
---------------------------------
class PaymentService {
    void pay(String type) {
        if(type.equals("CARD")) {}
        else if(type.equals("UPI")) {}
    }
}
✅ FIX
interface PaymentMethod { void pay(); }
class CardPayment implements PaymentMethod {}
class UpiPayment implements PaymentMethod {}

---------------------------------
❌ EXAMPLE 2
---------------------------------
class Discount {
    double calc(String type) {
        if(type.equals("NEW")) return 10;
        return 0;
    }
}
✅ FIX
interface DiscountStrategy { double calc(); }
class NewDiscount implements DiscountStrategy {}

---------------------------------
❌ EXAMPLE 3
---------------------------------
class Notification {
    void send(String t) {}
}
✅ FIX
interface NotificationType { void send(); }
class Email implements NotificationType {}
class SMS implements NotificationType {}

---------------------------------
❌ EXAMPLE 4
---------------------------------

}
✅ FIX

---------------------------------
❌ EXAMPLE 5

class Bus implements TransportMode {}

✅ KEY IDEA: Use interfaces + polymorphism

📌 L - LISKOV SUBSTITUTION PRINCIPLE (LSP)
=================================================
Definition:
Child should replace parent without breaking behavior

---------------------------------
❌ EXAMPLE 1
---------------------------------
class Bird { void fly() {} }
class Penguin extends Bird {
    void fly() { throw new UnsupportedOperationException(); }
}
✅ FIX
class Bird {}
interface Flyable { void fly(); }
class Sparrow extends Bird implements Flyable {}
class Penguin extends Bird {}

---------------------------------
❌ EXAMPLE 2
---------------------------------
class Vehicle { void startEngine() {} }
class Bicycle extends Vehicle {
    void startEngine() { throw new UnsupportedOperationException(); }
}
✅ FIX
class Vehicle {}
interface EngineVehicle { void startEngine(); }
class Car extends Vehicle implements EngineVehicle {}
class Bicycle extends Vehicle {}

---------------------------------
❌ EXAMPLE 3
---------------------------------
class File { void read() {} void write() {} }
class ReadOnlyFile extends File {
    void write() { throw new UnsupportedOperationException(); }
}
✅ FIX
interface Readable {}
interface Writable {}

---------------------------------
❌ EXAMPLE 4
---------------------------------
class Payment { void refund() {} }
class CashPayment extends Payment {
    void refund() { throw new UnsupportedOperationException(); }
}
✅ FIX
interface Payment {}
interface Refundable {}

---------------------------------
❌ EXAMPLE 5
---------------------------------
class Rectangle { int w,h; }
class Square extends Rectangle {}
✅ FIX
interface Shape {}
class RectangleShape implements Shape {}
class SquareShape implements Shape {}

✅ KEY IDEA: Child should not break behavior

=================================================
🔥 FINAL SHORTCUT
=================================================
SRP → Split responsibilities
OCP → Avoid if-else
LSP → Don't break parent behavior


=================================================
📘 I - INTERFACE SEGREGATION PRINCIPLE (ISP)
=================================================

📌 Definition
Clients should not be forced to depend on methods they do not use.

📌 Simple Definition
Use many small interfaces instead of one large interface.

📌 Memory Trick
Fat Interface ❌
Small Focused Interfaces ✅

=================================================
❌ EXAMPLE 1 - WORKER
=================================================

interface Worker {
    void work();
    void eat();
}

class Robot implements Worker {

    public void work() {}

    public void eat() {
        throw new UnsupportedOperationException();
    }
}

🚨 Problem
Robot does not eat but is forced to implement eat().

✅ FIX

interface Workable {
    void work();
}

interface Eatable {
    void eat();
}

class Human implements Workable, Eatable {

    public void work() {}

    public void eat() {}
}

class Robot implements Workable {

    public void work() {}
}

=================================================
📘 D - DEPENDENCY INVERSION PRINCIPLE (DIP)
=================================================

📌 Definition

High-level modules should not depend on low-level modules.
Both should depend on abstractions.

Abstractions should not depend on details.
Details should depend on abstractions.

📌 Simple Definition

Depend on Interfaces, Not Implementations.

📌 Memory Trick

Concrete Class ❌

Interface ✅

=================================================
❌ EXAMPLE 1 - NOTIFICATION
=================================================

class NotificationService {

    private EmailNotification email =
        new EmailNotification();

    void send() {
        email.send();
    }
}

🚨 Problem
NotificationService is tightly coupled to EmailNotification.

✅ FIX

interface Notification {
    void send();
}

class EmailNotification
implements Notification {

    public void send() {}
}

class SMSNotification
implements Notification {

    public void send() {}
}

class NotificationService {

    private Notification notification;

    NotificationService(
        Notification notification) {

        this.notification = notification;
    }

    void send() {
        notification.send();
    }
}
