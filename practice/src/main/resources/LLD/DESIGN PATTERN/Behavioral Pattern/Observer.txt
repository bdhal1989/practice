=================================================
📘 OBSERVER PATTERN - COMPLETE NOTES
=================================================

CATEGORY

Behavioral Design Pattern

=================================================
DEFINITION
=================================================

Observer Pattern is a Behavioral Design Pattern
that defines a One-To-Many dependency between
objects.

When one object changes state, all dependent
objects are automatically notified and updated.

Simple Rule:

Observer = Publish Subscribe

OR

Observer = One Changes, Many Get Notified

=================================================
WHY DO WE NEED IT?
=================================================

Suppose we have:

YouTube Channel

Subscribers

-------------------------------------------------

When a new video is uploaded:

All subscribers should receive
a notification.

-------------------------------------------------

WITHOUT OBSERVER

Channel manually calls:

notifyUser1();

notifyUser2();

notifyUser3();

notifyUser4();

-------------------------------------------------

Problems

❌ Tight Coupling

❌ Difficult To Add New Subscribers

❌ Difficult To Maintain

❌ Violates OCP

-------------------------------------------------

WITH OBSERVER

Channel
    |
    v

Observers

Automatically notified.

EXAMPLE 1 - YOUTUBE CHANNEL
=================================================

SCENARIO

YouTube Channel uploads video.

Subscribers receive notification.

-------------------------------------------------
IMPLEMENTATION MAPPING
-------------------------------------------------

Subject

---------------------------------

Concrete Subject

TechChannel

---------------------------------

Concrete Observer

-------------------------------------------------
JAVA IMPLEMENTATION
-------------------------------------------------

interface Subscriber {

    void update(
            String video);
}

-------------------------------------------------

class UserSubscriber
implements Subscriber {

    private String name;

    public UserSubscriber(
            String name) {

        this.name = name;
    }

    @Override
    public void update(
            String video) {

        System.out.println(
            name +
            " notified for "
            + video);
    }
}

-------------------------------------------------

class YouTubeChannel {

    private List<Subscriber>
            subscribers =
            new ArrayList<>();

    public void subscribe(
            Subscriber s) {

        subscribers.add(s);
    }

    public void uploadVideo(
            String video) {

        for(Subscriber s :
                subscribers) {

            s.update(video);
        }
    }
}

-------------------------------------------------

USAGE

YouTubeChannel channel =
        new YouTubeChannel();

channel.subscribe(
        new UserSubscriber("Bikash"));

channel.subscribe(
        new UserSubscriber("Rahul"));

channel.uploadVideo(
        "Observer Pattern");

=================================================
COMMON TEMPLATE
=================================================

Observer

interface Observer {

    void update();
}

-------------------------------------------------

Concrete Observer

class ConcreteObserver
implements Observer {

    public void update() {

        System.out.println(
            "Updated");
    }
}

-------------------------------------------------

Subject

interface Subject {

    void registerObserver(
            Observer observer);

    void removeObserver(
            Observer observer);

    void notifyObservers();
}

-------------------------------------------------

Concrete Subject

class ConcreteSubject
implements Subject {

    private List<Observer>
            observers =
            new ArrayList<>();

    public void notifyObservers() {

        for(Observer observer :
                observers) {

            observer.update();
        }
    }
}

=================================================
ADVANTAGES
=================================================

✔ Loose Coupling

✔ Supports Publish Subscribe

✔ Easy To Add New Observers

✔ Supports Open Closed Principle

✔ Reusable Design

✔ Event-Driven Architecture

=================================================
DISADVANTAGES
=================================================

❌ Too Many Notifications

❌ Difficult Debugging

❌ Notification Order Not Guaranteed

❌ Memory Leak If Observers
   Are Not Removed

=================================================
WHEN TO USE
=================================================

Use Observer When:

✔ One Object Depends On Many

✔ Automatic Notifications Required

✔ Event Driven Design Needed

Examples:

YouTube Subscribers

Stock Market

Weather Updates

Kafka Consumers

Spring Events

News Channels

=================================================
WHEN NOT TO USE
=================================================

Simple Direct Communication.

Few Objects.

No Subscription Needed.

=================================================
SOLID PRINCIPLES USED
=================================================

✅ OCP

New Observers Can Be Added
Without Modifying Subject.

---------------------------------

✅ DIP

Subject Depends On Observer
Interface.

Not Concrete Classes.

=================================================
OBSERVER vs STRATEGY
=================================================

STRATEGY

Changes Algorithm

Example:

UPI

CARD

PAYPAL

---------------------------------

OBSERVER

Notifies Multiple Subscribers

Example:

YouTube Channel

Subscribers

=================================================
OBSERVER vs MEDIATOR
=================================================

OBSERVER

One To Many Communication

Subject → Observers

---------------------------------

MEDIATOR

Many To Many Communication

Objects → Mediator → Objects

INTERVIEW ANSWER
=================================================

Observer Pattern is a Behavioral Design Pattern
that defines a One-To-Many dependency between
objects. When the Subject changes its state,
all registered Observers are automatically
notified and updated. It is widely used in
event-driven systems, Spring Events,
message brokers, and notification systems.
