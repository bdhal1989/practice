📘 PROTOTYPE PATTERN
=================================================

📌 DEFINITION

Prototype Pattern is a Creational Design Pattern
used to create new objects by copying (cloning)
an existing object instead of creating it from scratch.

Simple Rule:

Prototype = Copy Existing Object

-------------------------------------------------
📌 WHY DO WE NEED IT?
-------------------------------------------------

Sometimes object creation is:

✔ Expensive
✔ Time Consuming
✔ Repetitive

Instead of creating the same object again
and again using new(),

we create one object and make copies of it.

-------------------------------------------------
📌 SIMPLE REAL-LIFE EXAMPLE
-------------------------------------------------

Teacher creates:

1 Question Paper

Need:

100 Copies

Options:

❌ Write the same paper 100 times

OR

✅ Photocopy the original paper 100 times

Prototype Pattern = Photocopy Machine

-------------------------------------------------
📌 STORY
-------------------------------------------------

Suppose we are building a game.

Need:

1000 Soldiers

Every Soldier has:

✔ Gun
✔ Health = 100
✔ Power = 50
✔ Armor = Level 5

Creating each soldier from scratch is expensive.

-------------------------------------------------
❌ WITHOUT PROTOTYPE
-------------------------------------------------

Soldier s1 = new Soldier();

Soldier s2 = new Soldier();

Soldier s3 = new Soldier();

...

1000 times

Problems:

❌ Expensive Initialization

❌ Repeated Configuration

❌ Poor Performance

-------------------------------------------------
✅ WITH PROTOTYPE
-------------------------------------------------

Create one Soldier.

Soldier original =
    new Soldier();

Create copies.

Soldier s2 =
    original.clone();

Soldier s3 =
    original.clone();

====================================================================================-------------------------
📌 INTENT
-------------------------------------------------

Convert the interface of an existing class
into another interface expected by the client.

-------------------------------------------------
📌 PROBLEM
-------------------------------------------------

Application expects:

pay()

But Third Party Library provides:

makePayment()

Interfaces don't match.

Application and Library cannot work together.

-------------------------------------------------
✅ SOLUTION
-------------------------------------------------

Create an Adapter.

Application
      |
      v
Adapter
      |
      v
Third Party Library

Adapter converts:

pay()

to

makePayment()

-------------------------------------------------
📌 COMPONENTS
-------------------------------------------------

1. Client

Uses a target interface.

-----------------------------

2. Target

Expected interface.

Example:

interface PaymentProcessor {

    void pay();
}

-----------------------------

3. Adaptee

Existing class with incompatible interface.

Example:

class RazorpayGateway {

    void makePayment();
}

-----------------------------

4. Adapter

Converts one interface into another.

-------------------------------------------------
📌 COMPLETE EXAMPLE
-------------------------------------------------

STEP 1

Target Interface

interface PaymentProcessor {

    void pay();
}

-----------------------------

STEP 2

Existing Third Party Class

class RazorpayGateway {

    public void makePayment() {

        System.out.println(
            "Payment Successful"
        );
    }
}

-----------------------------

STEP 3

Adapter

class RazorpayAdapter
implements PaymentProcessor {

    private RazorpayGateway gateway =
            new RazorpayGateway();

    public void pay() {

        gateway.makePayment();
    }
}

-----------------------------

STEP 4

Usage

PaymentProcessor processor =
        new RazorpayAdapter();

processor.pay();

Output:

Payment Successful

📌 WHEN TO USE
-------------------------------------------------

Use Adapter When:

✔ Two interfaces are incompatible

✔ Legacy code must be reused

✔ Third-party APIs are integrated

✔ Data format conversion needed

Examples:

Payment Gateway

Food Delivery API

XML To JSON

Printer Drivers

-------------------------------------------------
📌 WHEN NOT TO USE
-------------------------------------------------

Interfaces already match.

Example:

interface PaymentProcessor

class StripePayment
implements PaymentProcessor

No adapter required.

-------------------------------------------------
📌 SOLID PRINCIPLES USED
-------------------------------------------------

-----------------------------

✅ DIP

Client depends on abstraction.

Instead of:

-------------------------------------------------
📌 ADAPTER vs FACTORY
-------------------------------------------------

Factory

Problem:

Which object should I create?

Example:

Car or Bike

-----------------------------

Adapter

Problem:

How can two incompatible
systems work together?

Example:

US Charger + Indian Socket

-------------------------------------------------
📌 ADAPTER vs BRIDGE
-------------------------------------------------

Adapter

Fixes Existing Incompatibility.

Example:

pay() vs makePayment()

-----------------------------

Bridge

Separates two dimensions
to avoid class explosion.

Example:

Remote + TV

Remote + Radio

-------------------------------------------------
🎯 INTERVIEW QUESTIONS
-------------------------------------------------

Q. What is Adapter Pattern?

Allows incompatible interfaces to
work together.

---------------------------------

Q. Why use Adapter Pattern?

To integrate legacy systems,
third-party APIs, or incompatible
interfaces without modifying them.

---------------------------------

Q. Real-life example?

Mobile Charger Adapter.

---------------------------------

Q. Adapter vs Factory?

Factory creates objects.

Adapter connects incompatible objects.

---------------------------------

Q. Adapter vs Bridge?

Adapter fixes incompatibility.

Bridge prevents class explosion.

-------------------------------------------------
🔥 INTERVIEW ANSWER
-------------------------------------------------

Adapter Pattern is a Structural Design Pattern
that allows two incompatible interfaces to work
together by introducing an adapter that converts
one interface into another expected by the client.

-------------------------------------------------
