📘 DECORATOR PATTERN - COMPLETE NOTES
=================================================

CATEGORY

Structural Design Pattern

=================================================
DEFINITION
=================================================

Decorator Pattern is a Structural Design Pattern
that allows us to add new functionality to an
object dynamically without modifying its code.

Simple Rule:

Decorator = Add Features Dynamically

=================================================
WHY DO WE NEED IT?
=================================================

Suppose we have:

Coffee

Customer wants:

Coffee + Milk

Coffee + Sugar

Coffee + Milk + Sugar

Coffee + Milk + Sugar + Cream

-------------------------------------------------

WITHOUT DECORATOR

Coffee

CoffeeWithMilk

CoffeeWithSugar

CoffeeWithMilkAndSugar

CoffeeWithMilkSugarCream

Problem:

❌ Too Many Classes

❌ Class Explosion

-------------------------------------------------

WITH DECORATOR

Coffee
  |
MilkDecorator
  |
SugarDecorator
  |
CreamDecorator

Features added dynamically.

=================================================
STRUCTURE
=================================================

Component
    |
Concrete Component
    |
Decorator
    |
Concrete Decorators

JAVA IMPLEMENTATION
-------------------------------------------------

interface Coffee {

    String getDescription();

    double getCost();
}

-------------------------------------------------

class SimpleCoffee
implements Coffee {

    @Override
    public String getDescription() {

        return "Coffee";
    }

    @Override
    public double getCost() {

        return 100;
    }
}

-------------------------------------------------

abstract class CoffeeDecorator
implements Coffee {

    protected Coffee coffee;

    public CoffeeDecorator(
            Coffee coffee) {

        this.coffee = coffee;
    }
}

-------------------------------------------------

class MilkDecorator
extends CoffeeDecorator {

    public MilkDecorator(
            Coffee coffee) {

        super(coffee);
    }

    @Override
    public String getDescription() {

        return coffee.getDescription()
                + " + Milk";
    }

    @Override
    public double getCost() {

        return coffee.getCost() + 20;
    }
}

-------------------------------------------------

USAGE

Coffee coffee =
    new MilkDecorator(
        new SimpleCoffee()
    );

=================================================
COMMON TEMPLATE
=================================================

interface Component {

    void operation();
}

-------------------------------------------------

class ConcreteComponent
implements Component {

    public void operation() {

        System.out.println(
                "Base Behavior");
    }
}

-------------------------------------------------

abstract class Decorator
implements Component {

    protected Component component;

    public Decorator(
            Component component) {

        this.component =
                component;
    }
}

-------------------------------------------------

class ConcreteDecorator
extends Decorator {

    public ConcreteDecorator(
            Component component) {

        super(component);
    }

    public void operation() {

        component.operation();

        System.out.println(
                "Extra Behavior");
    }
}

=================================================
ADVANTAGES
=================================================

✔ Add Functionality Dynamically

✔ Follows Open Closed Principle

✔ Avoids Class Explosion

✔ Flexible Design

✔ Reusable Components

✔ Runtime Behavior Changes

=================================================
DISADVANTAGES
=================================================

❌ More Objects

❌ More Complexity

❌ Harder Debugging

❌ Long Decorator Chains

=================================================
WHEN TO USE
=================================================

Use Decorator When:

✔ Features Are Optional

✔ Features Can Be Combined

✔ Behavior Added Dynamically

✔ Subclass Explosion Exists

Examples:

Coffee Shop

Pizza Toppings

Notifications

Car Features

Java IO Streams

=================================================
DECORATOR vs COMPOSITE
=================================================

COMPOSITE

Problem:

Tree Structure

Example:

Folder → File

Manager → Employee

Purpose:

Treat Individuals And Groups
Uniformly

---------------------------------

DECORATOR

Problem:

Add Features Dynamically

Example:

Coffee + Milk + Sugar

Purpose:

Add Extra Functionality

INTERVIEW ANSWER
=================================================

Decorator Pattern is a Structural Design Pattern
that allows additional behavior to be attached
to an object dynamically by wrapping it inside
decorator objects. It avoids subclass explosion
and follows the Open Closed Principle.
