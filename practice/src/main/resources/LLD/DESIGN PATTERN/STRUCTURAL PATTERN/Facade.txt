=================================================
📘 FACADE PATTERN - COMPLETE NOTES
=================================================

CATEGORY

Structural Design Pattern

=================================================
DEFINITION
=================================================

Facade Pattern is a Structural Design Pattern
that provides a simplified interface to a
complex subsystem.

Simple Rule:

Facade = One Entry Point To A Complex System

OR

Facade = Simplified Interface

=================================================
WHY DO WE NEED IT?
=================================================

Suppose a customer wants to watch a movie.

Without Facade:

TV.turnOn();

SoundSystem.turnOn();

SoundSystem.setVolume();

StreamingDevice.turnOn();

StreamingDevice.playMovie();

Lights.dim();

-------------------------------------------------

Client must understand every subsystem.

Problem:

❌ Too Many Objects

❌ Too Much Complexity

❌ Tight Coupling

❌ Difficult To Use

-------------------------------------------------

Solution:

MovieFacade.watchMovie();

Single method call.

=================================================
CORE IDEA
=================================================

Facade sits in front of a complex system.

Client
   |
   v
Facade
   |
   v

Subsystem A

Subsystem B

Subsystem C

Subsystem D

Client talks only to Facade.

=================================================
COMPONENTS
=================================================

1. Client

Uses the facade.

---------------------------------

2. Facade

Simplified interface.

---------------------------------

3. Subsystems

Actual business logic classes.

EXAMPLE 1 - HOME THEATER SYSTEM
=================================================

SCENARIO

To watch a movie we need:

✔ TV

✔ Sound System

✔ Streaming Device

✔ Lights

-------------------------------------------------
WITHOUT FACADE
-------------------------------------------------

tv.on();

soundSystem.on();

soundSystem.setVolume(50);

streamingDevice.on();

streamingDevice.playMovie();

lights.dim();

-------------------------------------------------
IMPLEMENTATION MAPPING
-------------------------------------------------

Facade

HomeTheaterFacade

---------------------------------

Subsystems

TV

SoundSystem

StreamingDevice

Lights

-------------------------------------------------
JAVA IMPLEMENTATION
-------------------------------------------------

class TV {

    public void on() {

        System.out.println(
            "TV ON");
    }
}

-------------------------------------------------

class SoundSystem {

    public void on() {

        System.out.println(
            "Sound System ON");
    }
}

-------------------------------------------------

class StreamingDevice {

    public void playMovie() {

        System.out.println(
            "Playing Movie");
    }
}

-------------------------------------------------

class HomeTheaterFacade {

    private TV tv =
            new TV();

    private SoundSystem sound =
            new SoundSystem();

    private StreamingDevice device =
            new StreamingDevice();

    public void watchMovie() {

        tv.on();

        sound.on();

        device.playMovie();
    }
}

-------------------------------------------------

USAGE

HomeTheaterFacade facade =
        new HomeTheaterFacade();

facade.watchMovie();

COMMON TEMPLATE
=================================================

Subsystem A

class SubsystemA {

    void actionA() {

    }
}

-------------------------------------------------

Subsystem B

class SubsystemB {

    void actionB() {

    }
}

-------------------------------------------------

Facade

class Facade {

    private SubsystemA a =
            new SubsystemA();

    private SubsystemB b =
            new SubsystemB();

    public void operation() {

        a.actionA();

        b.actionB();
    }
}

=================================================
ADVANTAGES
=================================================

✔ Simplifies Complex Systems

✔ Reduces Coupling

✔ Improves Readability

✔ Easier Maintenance

✔ Hides Internal Complexity

✔ Cleaner Client Code

=================================================
DISADVANTAGES
=================================================

❌ Facade Can Become Large

❌ May Hide Useful Features

❌ Extra Layer Of Abstraction

=================================================
WHEN TO USE
=================================================

Use Facade When:

✔ Complex Subsystems Exist

✔ Client Uses Multiple Objects

✔ Need Simple API

Examples:

Home Theater

Food Ordering

Banking

Travel Booking

E-Commerce

Spring Service Layer

=================================================
WHEN NOT TO USE
=================================================

Simple Systems

Example:

User user = new User();

No Facade Needed.

=================================================
SOLID PRINCIPLES USED
=================================================

✅ OCP

New Subsystems Can Be Added
Without Affecting Clients.

---------------------------------

✅ DIP

Clients Depend On Facade

Not On Internal Classes.

=================================================
FACADE vs ADAPTER
=================================================

ADAPTER

Problem:

Interfaces Are Incompatible

Example:

pay()

makePayment()

Purpose:

Translator

---------------------------------

FACADE

Problem:

System Is Too Complex

Purpose:

Simplified Interface

=================================================
FACADE vs DECORATOR
=================================================

DECORATOR

Adds New Behavior

Example:

Coffee + Milk

---------------------------------

FACADE

Simplifies Existing System

Example:

Home Theater

INTERVIEW ANSWER
=================================================

Facade Pattern is a Structural Design Pattern
that provides a unified and simplified interface
to a set of interfaces in a subsystem. It hides
the complexity of the subsystem and makes it
easier for clients to use.
