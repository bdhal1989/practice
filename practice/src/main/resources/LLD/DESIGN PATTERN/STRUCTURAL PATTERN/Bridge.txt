=================================================
📘 BRIDGE PATTERN - COMPLETE NOTES
=================================================

CATEGORY

Structural Design Pattern

=================================================
DEFINITION
=================================================

Bridge Pattern is a Structural Design Pattern
that separates Abstraction from Implementation
so that both can evolve independently.

Simple Rule:

Bridge = Separate Two Dimensions

=================================================
WHY DO WE NEED IT?
=================================================

Suppose a system has two independently changing
parts.

Example:

Remote Types
✔ Basic Remote
✔ Advanced Remote
✔ Smart Remote

Device Types
✔ TV
✔ Radio
✔ AC

If every remote is combined with every device,
classes grow rapidly.

This leads to Class Explosion.

=================================================
CORE IDEA
=================================================

Abstraction
      |
      HAS-A
      |
Implementation

Examples:

Remote HAS-A Device
Shape HAS-A Color
Payment HAS-A Bank
Vehicle HAS-A Engine

=================================================
EXAMPLE 1 - REMOTE + DEVICE
=================================================

Abstraction
------------
Remote

Implementation
------------
Device

Java Implementation

interface Device {
    void on();
    void off();
}

class TV implements Device {}
class Radio implements Device {}

abstract class Remote {

    protected Device device;

    public Remote(Device device) {
        this.device = device;
    }

    abstract void power();
}

class BasicRemote
extends Remote {

    public BasicRemote(Device d) {
        super(d);
    }

    void power() {
        device.on();
    }
}

Usage

Remote remote =
    new BasicRemote(new TV());

=================================================
ADVANTAGES
=================================================

✔ Prevents Class Explosion
✔ Loose Coupling
✔ Better Maintainability
✔ Composition Over Inheritance
✔ Easy Extension

=================================================
DISADVANTAGES
=================================================

❌ More Classes
❌ More Complexity
❌ Harder To Understand Initially

=================================================
WHEN TO USE
=================================================

✔ Two Dimensions Exist
✔ Both Change Independently
✔ Many Combinations Exist

Examples:

Remote + Device
Shape + Color
Payment + Bank
Notification + Channel
Vehicle + Engine
