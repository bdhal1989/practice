Consistent hashing is a technique used to distribute data across multiple nodes (servers/shards) such that when nodes are added or removed, only a small portion of the data needs to be remapped.


✅ ✅ Why Consistent Hashing Arose (Very Important 🔥)
🔴 Problem Before (Traditional Hashing)
Earlier systems used:
shard = hash(key) % N


🔴 What Was the Issue?
👉 When system grows:
✅ Case: Add a new shard
Before:
N = 3 → hash(key) % 3

After:
N = 4 → hash(key) % 4


❌ Result:

Almost ALL keys change their shard
Huge data movement
System instability
Downtime risk


✅ Example
Key = 123

Before:
123 % 3 = 0 → Shard-0

After:
123 % 4 = 3 → Shard-3 ❌

👉 ❗ Every key moves → not scalable ❌

✅ ✅ Real-World Problems Caused
Because of this issue:

❌ Adding servers became expensive
❌ Rebalancing took time
❌ System performance dropped
❌ Possible data inconsistency


✅ ✅ Solution: Consistent Hashing
👉 Engineers needed:

✅ A way to scale easily
✅ Avoid massive data reshuffling
✅ Keep system stable

✅ ✅ 3. INTERVIEW Q&A PRACTICE

✅ Q1: Why not use simple hashing?
Answer:

In modulo-based hashing, adding or removing a shard causes massive data reshuffling. Consistent hashing avoids this by mapping data and shards on a hash ring, ensuring minimal data movement.


✅ Q2: How does consistent hashing work?
Answer:

It places both shards and data on a circular hash ring. Each key is assigned to the nearest shard in a clockwise direction.


✅ Q3: What happens when a shard is added?
Answer:

Only the data between the new shard and its previous shard moves. The rest of the data remains unchanged.


✅ Q4: What problem does it solve?

Reduces data movement
Makes scaling easier
Improves system stability


✅ Q5: What is a drawback?

Uneven distribution of keys across shards.


✅ Q6: Solution to uneven distribution?

Use virtual nodes where each shard is placed multiple times on the ring.

✅ Consistent Hashing Notes
Problem with Modulo Hashing:
- shard = hash(key) % N
- Adding/removing shard → all data moves

Solution: Consistent Hashing

Concept:
- Use a circular hash ring
- Place both shards and keys on ring
- Assign key → nearest shard (clockwise)

Steps:
1. Hash shards → positions on ring
2. Hash keys → positions
3. Move clockwise → find shard

Advantages:
- Minimal data movement
- Easy scaling
- Better stability

Disadvantage:
- Uneven distribution

Solution:
- Virtual nodes (multiple positions per shard)

Real-world usage:
- Cassandra
- DynamoDB
- Kafka
- CDN systems


Code

import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;
import java.util.*;

public class ConsistentHashing {

    // TreeMap to store hash ring (sorted)
    private final TreeMap<Integer, String> ring = new TreeMap<>();

    // Add shard
    public void addShard(String shard) {
        int hash = hash(shard);
        ring.put(hash, shard);
    }

    // Remove shard
    public void removeShard(String shard) {
        int hash = hash(shard);
        ring.remove(hash);
    }

    // Find shard for a key
    public String getShard(String key) {
        if (ring.isEmpty()) return null;

        int hash = hash(key);

        // Find first shard >= hash
        Map.Entry<Integer, String> entry = ring.ceilingEntry(hash);

        // If not found, wrap to first shard
        if (entry == null) {
            entry = ring.firstEntry();
        }

        return entry.getValue();
    }

    // Hash function using MD5
    private int hash(String key) {
        try {
            MessageDigest md = MessageDigest.getInstance("MD5");
            byte[] digest = md.digest(key.getBytes());

            int hash = 0;
            for (int i = 0; i < 4; i++) {
                hash = (hash << 8) + (digest[i] & 0xFF);
            }

            return hash & 0x7fffffff; // positive integer

        } catch (NoSuchAlgorithmException e) {
            throw new RuntimeException(e);
        }
    }

    // Test main method
    public static void main(String[] args) {
        ConsistentHashing ch = new ConsistentHashing();

        // Add shards
        ch.addShard("Shard-1");
        ch.addShard("Shard-2");
        ch.addShard("Shard-3");

        // Test keys
        String[] keys = {"user123", "user456", "user789"};

        for (String key : keys) {
            System.out.println(key + " → " + ch.getShard(key));
        }

        // Add new shard
        System.out.println("\nAdding Shard-4...\n");
        ch.addShard("Shard-4");

        for (String key : keys) {
            System.out.println(key + " → " + ch.getShard(key));
        }
    }
}


Problem (Modulo Hashing):
- shard = hash(key) % N
- Adding/removing shard → all data moves ❌

Consistent Hashing Solution:
- Use circular hash ring
- Place shards and keys on ring
- Assign key → nearest shard (clockwise)

Steps:
1. Hash shards → positions on ring
2. Hash keys → positions
3. Move clockwise to find shard

Key Property:
- Minimal data movement when adding/removing shards

Example:
Before:
Shard-1 → Shard-2 → Shard-3

After adding Shard-4:
Shard-1 → Shard-4 → Shard-2 → Shard-3

Only data between:
Shard-1 → Shard-4 moves ✅

Advantages:
- Scalable
- Fault-tolerant
- Minimal reshuffling

Problem:
- Uneven distribution

Solution:
- Virtual Nodes (multiple positions per shard)

Virtual Nodes:
Shard-1 → multiple hashes
Shard-2 → multiple hashes
Improves load balance

Some shards get more data, others get very little
