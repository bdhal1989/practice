 Q1: What is sharding?
Expected Answer:

Sharding is a technique to horizontally partition data across multiple databases (shards), where each shard contains a subset of the data.


✅ Q2: Why do we use sharding?
Answer:

Scalability
Performance improvement
Avoid single DB bottleneck


✅ Q3: What is a shard key?
Answer:

A shard key is a column used to determine which shard the data should go to (e.g., user_id).


✅ ✅ 🟡 MEDIUM QUESTIONS (MOST IMPORTANT 🔥)

✅ Q4: How do you choose a good shard key?
Answer:

High cardinality
Even distribution
Frequently used in queries


✅ Q5: Difference between horizontal and vertical sharding?
Answer:
Horizontal:
- Split rows
- Same tables on each shard

Vertical:
- Split tables
- Different tables on different shards


✅ Q6: What is the problem with sharding?
Answer:

Cross-shard queries
Resharding difficulty
Data consistency
Hotspots


✅ Q7: How do you handle cross-shard queries?
Answer:

Avoid joins
Denormalize data
Use aggregation layer
Query all shards (scatter-gather)


✅ Q8: What happens when you add a new shard?
Answer:

Data needs redistribution
Use consistent hashing to reduce movement


✅ ✅ 🔴 ADVANCED QUESTIONS (INTERVIEW GOLD 🔥)

✅ Q9: Why is consistent hashing used?
Answer:

It minimizes data movement when shards are added or removed by mapping data and nodes on a hash ring.



✅ Q10: Explain hotspot problem and solution
Answer:

Hotspot occurs when one shard gets too much traffic due to poor shard key selection.
Solutions:


Better shard key
Hash-based sharding
Virtual nodes



✅ Q11: How do you combine sharding with replication?
Answer:
Each shard:
Primary → Replicas

Sharding → distributes data  
Replication → ensures availability & read scaling



✅ Q12: How do you handle transactions across shards?
Answer:

Use eventual consistency
Saga pattern
Avoid distributed transactions if possible



✅ Q13: How would you design sharding for Instagram?
Expected Answer:

Shard by user_id
Store user + posts + likes together
Avoid cross-shard joins
Use caching + replication



✅ Q14: What is resharding and its challenges?
Answer:

Re-sharding means redistributing data when new shards are added.

Challenges:

Data migration
Downtime risk
Consistency



✅ Q15: How do you avoid uneven distribution in consistent hashing?
Answer:

Use virtual nodes to distribute load evenly across shards.

 Feed Generation (CORE Instagram Problem 🔥)
👉 Question was:

How does user B see posts from users they follow?


✅ ✅ Two Main Approaches
🔴 1. Pull Model (Fan-out on Read)

✅ Concept
User opens app → system fetches posts from all followed users in real-time


✅ Flow
User B follows: A, C, D

User B opens app →
Fetch posts:
   A → posts
   C → posts
   D → posts
Merge + sort → show feed


✅ Diagram
User → Feed Service
         ↓
Fetch from multiple shards/users
         ↓
Merge + sort
         ↓
Show feed


✅ Pros

✅ Simple
✅ No extra storage


❌ Cons

❌ Slow (many DB calls)
❌ Doesn't scale (100M users)


🟢 2. Push Model (Fan-out on Write)

✅ Concept
User creates post → system pushes this post into followers’ feeds


✅ Flow
User A posts →
Find followers (B, C, D)
Push post into:
   B's feed
   C's feed
   D's feed


✅ Diagram
User A → Post Service
          ↓
     Fan-out
   /    |    \
 B      C     D
(feed) (feed) (feed)


✅ Pros

✅ Fast feed read ✅
✅ Very scalable for reads


❌ Cons

❌ Expensive on write
❌ Storage overhead


✅ ✅ 3. Real-World (Instagram Uses HYBRID)
👉 Neither pure push nor pull

✅ Strategy
✅ For NORMAL users:
Push model ✅

👉 Few followers → easy to push

✅ For CELEBRITIES:
Pull model ✅

👉 Millions of followers → cannot push to everyone ❌

✅ ✅ Hybrid Diagram
User Post →
   ↓
IF normal user → push to followers ✅
IF celebrity  → store only, fetch later ✅


✅ ✅ Precompute vs Real-time

✅ Precompute (= Push Model)
Feed already prepared BEFORE user opens app ✅

👉 Fast reads

✅ Real-time (= Pull Model)
Feed created WHEN user opens app ❌

👉 Slower

✅ ✅ Final Interview Answer (Very Important 🔥)
👉 You should say:

“Feed generation can be handled using pull and push models. In the pull model, the system fetches posts from followed users at read time, which is simple but slow at scale. In the push model, the system precomputes feeds by pushing posts to followers at write time, which makes reads fast but increases write cost. In practice, systems like Instagram use a hybrid approach—using push for normal users and pull for celebrities with a large follower base.”
